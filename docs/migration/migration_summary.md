## Phase 3 Addendum — pandas 3.x compatibility fix (2026-08-12)

**Bug (pre-existing; surfaced by the global env running pandas 3.0.5 vs the pyproject pin pandas<3.0):** `clean_zomato` assigned cleaned float Series via in-place `df.loc[:, col] = ...` into existing string-dtype columns (`rate`, `approx_cost(for two people)`). pandas >= 3 enforces a strict string dtype and raises `TypeError: Invalid value '[4.1 3. ]' for dtype 'str'`; pandas 2.x silently upcast. This broke 3 tests in `tests/test_cleaning.py` (TestCleanZomato).

**Fix (zero behavior change):** switched the two assignments to column replacement (`df[col] = ...`), which replaces the column with the cleaned float Series — byte-identical output on pandas 2 and 3+ (verified: all test assertions encode the pandas-2 behavior and now pass on pandas 3.0.5).

**Verification (evidence):**

| CI-equivalent suite | `pytest tests/ --timeout=60 --ignore=tests/e2e --ignore=tests/integration --ignore=tests/test_db_loaders.py --ignore=tests/test_eta_model.py --ignore=tests/test_rating_model.py --ignore=tests/test_optuna_tuning.py --ignore=tests/test_hinglish_sentiment.py -k "not optuna and not train and not full_import"` | 221 passed, 10 deselected |

**CI status:** CI installs from pyproject (`pandas>=2.0,<3.0` → pandas 2.x) so the 3 tests already passed under the pin; the fix additionally makes them pass on pandas 3/4.
